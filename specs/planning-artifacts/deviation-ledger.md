# Deviation Ledger

Canonical, enumerable register of every recorded divergence from a canonical expectation in the
`ui-toolkit` `v1.0.0` release.

- **Purpose** — satisfy `epics.md` Story 5.2 acceptance 2 ("the deviation is explicitly justified
  and recorded" / "the decision is visible for release review", `epics.md:695-698`) from a single
  enumerable surface. Before this file existed the same information was split three ways: free
  prose inside `component-provenance.md` rationale cells, the board-scoped `D-01`-`D-18` table in
  `board-coverage-checklist.md:174-191`, and per-story tables buried in the implementation
  artifacts. Nothing enumerated them together, so no reviewer could count them, and code-level
  deviations that were never written into any artifact (the nine WCAG 1.4.11 decoration
  exemptions, the `field-controls` focus stroke) were invisible to release review entirely.
- **Owner** — Component Lead / Frontend Team (`prd.md:135`).
- **Governing requirements** — `prd.md` §3.5 ("Documented exceptions are allowed only where control
  semantics require it", `prd.md:69`), `prd.md` FR-07 acceptance 2 ("Exceptions are documented with
  rationale", `prd.md:221`), `prd.md` FR-02 (`prd.md:155-162`), `prd.md` FR-01 acceptance 2
  (`prd.md:153`); `epics.md` Story 5.2 "Reuse/Canonical Compliance and Provenance Completion"
  (`epics.md:682-703`); issue [#32](https://github.com/VilnaCRM-Org/ui-toolkit/issues/32).
- **Machine-checked** — the Story 5.2 drift guard
  `tests/unit/component-provenance-traceability.test.ts` parses this file together with
  `component-provenance.md` and fails the unit suite when a `Kind` or `Status` cell carries a token
  outside the allowed set, when an `Owner + tracking ref` cell is empty, when a `DEV-nn` id cited by
  a registry row has no row here, or when a `Recorded where` cell names a file that does not exist.
  Edit this file and the drift guard together.

Rows are appended, never renumbered: a `DEV-nn` id is permanent, and a deviation that is retired is
marked `superseded` rather than deleted, so the audit trail survives.

## How to read this file

**Column contract.**

| Column                             | Contract                                                                                                                                                                                                                                            |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ID`                               | `DEV-nn`, unique and contiguous. `DEV-01`-`DEV-18` mirror `board-coverage-checklist.md:174-191` (`D-01`-`D-18`) one for one and are imported **by reference**: the decision text lives there and is never restated here. `DEV-19`+ are new records. |
| `Component/module`                 | The exported symbol, or the module path when the deviation is not on the public export surface.                                                                                                                                                     |
| `Deviation`                        | What diverges, in one sentence. For imported rows, a summary plus the `see D-nn` back-reference.                                                                                                                                                    |
| `Canonical expectation + citation` | The thing the implementation is measured against, cited so it can be checked without reading the code: a `prd.md` section plus line, a WCAG 2.2 Success Criterion number, an upstream `crm`/`website` path plus audited commit, or a Figma node id. |
| `Justification`                    | Why the divergence is defensible. A row with no justification is a defect, not a deviation.                                                                                                                                                         |
| `Kind`                             | Exactly one token from the closed set below.                                                                                                                                                                                                        |
| `Status`                           | Exactly one token from the closed set below.                                                                                                                                                                                                        |
| `Owner + tracking ref`             | `<owner role or story> · <ref>`, where `<ref>` is either a filed GitHub issue `#NNN` or the literal fallback `unfiled:<owning-story-or-team>`. Never empty — an untrackable deviation is not production-review ready.                               |
| `Recorded where`                   | The artifact that carries the decision, as a repo-relative path. Implementation artifacts are cited by section heading rather than by line, because their header blocks shift when metadata is repaired.                                            |

**Kind tokens.** Exactly one of five literal tokens:

| Token                | Meaning                                                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `contract-exception` | A field of the `prd.md` §3.5 shared contract (`value`/`onChange`/`disabled`/`error`/`size`/`variant`/`sx`) is not supported.  |
| `visual-parity`      | The rendered result deliberately differs from the Figma master, or the design ships no master for a state the toolkit paints. |
| `a11y-conformance`   | An accessibility decision that departs from the default reading of a WCAG 2.2 Success Criterion, or defers its visual half.   |
| `reuse-deviation`    | A departure from the `prd.md` §3.2/§3.3 reuse-first and canonical-source rules, including duplication and scope leakage.      |
| `non-goal`           | Board-painted or spec-adjacent work deliberately excluded from `v1.0.0` scope.                                                |

**Status tokens.** Exactly one of five literal tokens:

| Token                  | Meaning                                                                                                                    |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `ratified`             | A named authority (the PRD, or the owner in a merged story) has signed the ruling off. No further decision is outstanding. |
| `pending-ratification` | The ruling is recorded but not yet confirmed by its owner. It has a row in the ratification register below.                |
| `escalated`            | Raised to the designer or release owner because the source of truth is missing or ambiguous; no ruling exists yet.         |
| `deferred-tracked`     | Accepted for `v1.0.0` and routed to named follow-up work. Never "closed" — it stays open until the follow-up lands.        |
| `superseded`           | Replaced by a later row or by delivery. Kept for the audit trail. Unused at `v1.0.0`.                                      |

**No-widening rule.** A failing drift-guard assertion is closed by recording evidence, never by
widening a token set, relaxing a citation requirement, or deleting a row.

  (Board B period segmented switcher), `DEV-17` (`UiSkeletonWidget` wide block and chart widgets),

  ledger row because it is an appendix ruling rather than a deviation — it appears in the
  ratification register below instead.
- **Non-blocking fidelity and evidence follow-ups — `unfiled:frontend-team`.** `DEV-02`
  (`socialButton` per-state visual grid) and `DEV-04` (`UiSearchInput` suggestion prefix-highlight).
- **Toolkit-hygiene rulings — `unfiled:component-lead`.** `DEV-40` (container sizing declared in two

- **Board A out-of-scope paints — `unfiled:component-lead`.** `DEV-44` through `DEV-50`, the seven
