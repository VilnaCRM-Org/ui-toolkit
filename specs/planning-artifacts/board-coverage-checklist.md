# Board Coverage Checklist

Canonical board-to-component coverage map for the `ui-toolkit` `v1.0.0` release.

- **Purpose** — prove, from a single source of truth, that every board element required by
  `prd.md` §4 maps to a delivered toolkit component or to an explicit non-goal decision, and that
  each mapping carries export, Storybook, and unit-test evidence that can be verified without
  re-reading the implementation.
- **Owner** — Component Lead / Frontend Team (`prd.md:135`).
- **Governing requirements** — `prd.md` FR-01 (`prd.md:146-153`), `prd.md` §5.6 (`prd.md:135`),
  `prd.md` §9.1 (`prd.md:245`); `epics.md` Story 5.1 "Board Coverage Closure and Traceability"
  (`epics.md:659-680`); issue [#31](https://github.com/VilnaCRM-Org/ui-toolkit/issues/31).
- **Machine-checked** — `tests/unit/board-coverage-traceability.test.ts` parses this file and fails
  the unit suite when a row's backticked export identifier is missing from
  `src/components/index.ts`, when a referenced story or test path does not exist on disk, when a
  row carries a status token outside the allowed set, or when the per-board counts drift from the
  rows above them. Edit this file and the drift-guard together.

New rows are appended by the delivering story. Existing rows are updated (not rewritten) when a
later story enhances a component.

## How to read this file

**Status tokens.** The implementation-status column uses exactly one of three literal tokens:

| Token      | Meaning                                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| `Done`     | The board element is mapped to a delivered component that is exported, storied, and unit-tested.                          |
| `Non-goal` | The board element is deliberately not delivered, under an explicit recorded decision (FR-01 acceptance 2).                |
| `Blocked`  | The board element is neither delivered nor ruled a non-goal. Unresolved; see [Unresolved blockers](#unresolved-blockers). |

**Scope of `Done`.** `Done` asserts _delivery evidence_ — the component is on the public export
surface, has at least one Storybook story, and has unit tests. It does **not** assert per-epic
quality-gate sign-off: Stories 1.4 ([#27](https://github.com/VilnaCRM-Org/ui-toolkit/issues/27)),
2.6 ([#28](https://github.com/VilnaCRM-Org/ui-toolkit/issues/28)),
3.6 ([#29](https://github.com/VilnaCRM-Org/ui-toolkit/issues/29)) and
4.4 ([#30](https://github.com/VilnaCRM-Org/ui-toolkit/issues/30)) still own gate closure, and
`prd.md` §9 criteria 2-7 are consolidated by Story 5.4, not here.

**Storybook coverage column.** Each cell names the story file and the primary Storybook story id.
The toolkit has **no public Storybook deployment**
(issue [#88](https://github.com/VilnaCRM-Org/ui-toolkit/issues/88)), so the "URL" required by
`prd.md` §5.6 resolves locally against a running dev server or a static build:

```text
http://localhost:6006/iframe.html?id=<storyId>&viewMode=story   # storybook dev
storybook-static/iframe.html?id=<storyId>&viewMode=story        # storybook build
```

Story ids are the same ids enumerated in `tests/visual/stories.json`, so the column is verifiable
against a committed manifest rather than against a live host.

**Unit test coverage column.** Each cell names the unit test files that lock the component's
behaviour. There is no published coverage artifact either — Codecov is configured but non-blocking
and carries no `codecov.yml` (issue [#103](https://github.com/VilnaCRM-Org/ui-toolkit/issues/103))
— so the "coverage report link" resolves to the locally generated report:

```text
coverage/lcov-report/index.html                                 # suite entry point
coverage/lcov-report/src/components/<component-dir>/index.html  # per-component entry point
```

**Figma provenance.** Board frames live in file `xZ7ccrH6d4QyqLQsayFSEX`, page "Ui kit"
(`439:19251`): Board A `439:19252`, Board B `439:19374`, Board C `439:19893`, Board D `538:38316`.
Per-component node ids and measured deviations are recorded in `component-provenance.md`.

### BLOCK-01 — Board A §4.1 item 3, "Link states": RESOLVED (delivered in Story 5.1, #31)

**What was blocked.** Board A (`439:19252`) is a four-column state grid — Rest (`439:19261`), Hover
(`439:19263`), Active (`439:19264`), Disabled (`439:19265`) — and the link row is painted in all
four: `439:19361` (rest), `439:19362` (hover), `439:19363` (active), `439:19364` (disabled); the
same holds for the second link row `439:19611`-`439:19614`. The disabled column is a **distinct**
paint, not a copy of rest: rest `439:19361` measures `#969B9D` (token Font/300 Placeholder) and
disabled `439:19364` measures `#E1E7EA` (token Brand gray). `prd.md:182` (FR-04 acceptance 4)
independently requires `UiLink` to expose `disabled`, but `src/components/ui-link/types.ts` declared
`disabled` a contract exception and no prop, styling or test existed.

**Resolution (Story 5.1, closure path "Deliver").**

1. Re-measured the two disabled cells against their rest counterparts: ink `#E1E7EA` vs `#969B9D`,
   with **no** typography or text-decoration delta (identical glyph coverage at identical size), so
   the disabled treatment repaints the ink only.
2. `src/components/ui-link/types.ts` — `disabled?: boolean` added to the contract; the exception
   list shrank to `value`, `onChange`, `error`, `size`, `variant`.
3. `src/components/ui-link/index.tsx` — the anchor keeps its `href` (and therefore its `link` role
   and accessible name) and additionally renders `aria-disabled="true"`, `tabIndex={-1}` (the Story
   1.3 tab-order-exclusion pattern) and a click handler that cancels activation.
4. `src/components/ui-link/theme.ts` — `&[aria-disabled="true"]` sets `color` to the `brandGray`
   token (`#E1E7EA`) from `ui-color-theme`, with nested `:hover`/`:active` resets so the
   interactive accents cannot fire while disabled. No hex literal was introduced.
5. Coverage — `src/components/ui-link/link.stories.tsx` gained a `disabled` boolean control (forced
   through a story-arg URL, so no new story export); `tests/visual/states.spec.ts` gained the
   `link-disabled.png` baseline; `tests/unit/ui-link.test.tsx` and
   `tests/unit/core-controls-accessibility.test.tsx` pin the ARIA flag, the tab-order exclusion,
   the suppressed navigation, the unchanged enabled behaviour, and the new-tab `rel`/notice
   contract under `disabled`.
6. `component-provenance.md` (Epic 1, `UiLink` row) now records `rest/hover/active/disabled` with
   the node ids and the token used; `error` remains the sole documented contract exception, which
   FR-04 marks optional.
