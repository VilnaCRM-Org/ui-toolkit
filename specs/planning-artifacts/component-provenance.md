# Component Provenance Registry

Central source-provenance registry for the toolkit, mandated by
`architecture.md#provenance--governance-patterns` and `epics.md` (FR: provenance
tracked centrally with `crm | website | new` source labels and rationale).

For each delivered or enhanced component, record:

- **source** — `crm` (canonical behavior), `website` (visual/variant gap-fill), or `new`
- **rationale** — why that source is canonical for this component
- **alignment notes** — behavior/visual decisions and any documented deviations

New entries are appended by the delivering story. Existing entries are updated
(not rewritten) when a later story enhances a component; a claim that turns out
to be wrong is corrected in place, **dated and marked as a correction**, never
silently overwritten. When a module reaches the toolkit with no delivering story
— the pre-Epic-1 parity layer that arrived through the stack PRs, and any module
a later refactor extracts — the rule assigns an owner instead of leaving the row
unwritten: **Story 5.2 ([#32](https://github.com/VilnaCRM-Org/ui-toolkit/issues/32))
is the named backfill owner** for every module already on the surface at the time
of writing, and any module that lands unowned after it is recorded by the closure
story of the epic that lands it. No module may sit outside the registry on the
grounds that no story claimed it.

## Scope

**Coverage contract.** Every symbol exported from `src/components/index.ts` MUST
have exactly one row in this registry — the 55 `export { default as … }`
components and the 8 named theme/breakpoint symbols (`crmColorTheme`,
`sharedPalette`, `websiteColorTheme`, `crmBreakpointValues`,
`crmBreakpointsTheme`, `heightBreakpoints`, `websiteBreakpointValues`,
`websiteBreakpointsTheme`), 63 symbols in total. That explicitly includes the
pre-Epic-1 seeded modules (`### Epic 0 — Seeded parity baseline`) and the two
token surfaces, which every pass before Story 5.2 left unrecorded. The defect
being closed is ambiguity, not volume: with no coverage contract there was no way
to tell an **unrecorded** module from a **deliberately excluded** one. The two
token rows name their eight symbols in the Component cell, so the whole
theme/breakpoint surface resolves through them.

**Row key.** The Component cell is `` `<ExportedName>` (`<src/components/… path>`) ``
so a row is machine-parseable and keys back to the barrel. A row whose subject is
**not** on the public export surface carries a trailing `` · `internal` `` flag;
that flag is what lets the drift guard tell a deliberately internal module from a
missing export.

**Deviation clause.** Every row ends with either `Deviations: none …` or
`Deviations: DEV-nn, …`. The `DEV-nn` ids resolve in
`specs/planning-artifacts/deviation-ledger.md`; this registry cites ids and never
restates ledger rows.

**Internal modules — no row required.** These three are on disk under
`src/components/` but not on the public export surface, so the coverage contract
does not reach them:

| Module                      | Why no row is owed                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/components/app-theme`  | A composed `createTheme` assembled from `ui-breakpoints` + `ui-color-theme` + `ui-typography`; it is not exported from the barrel and has no runtime consumer in `src/` (verified — the only reference is its own suite `tests/unit/app-theme.test.ts`). Its `MuiContainer` override does overlap `ui-container`, which is recorded as a deviation rather than a row (DEV-40). |
| `src/components/fonts.css`  | A stylesheet, not a module — it declares `@font-face` only and exports no symbol. Side-effect-imported, see the note below (DEV-43).                                                                                                                                                                                                                                           |
| `src/components/types.d.ts` | Ambient `declare module '@mui/material/styles'` augmentation for the custom typography variants; it declares types only and emits nothing at runtime.                                                                                                                                                                                                                          |

**The one exception — `field-controls`.** `src/components/field-controls` is also
off the export surface, but it holds delivered cross-component _behaviour_ (the
ghost-completion overlay `GhostOverlay`, the shared `createFieldRenderInput`,
`createFieldOptionRenderer`, `useFieldAccessibilityWarnings` and the shared
`Glyph`), consumed at runtime by 15 sibling modules, so it carries a real row in
the Epic 2 table with source `new` and the `internal` flag.

**Fonts.** `src/components/index.ts:1` is `import './fonts.css';` — a side-effect
import, so every consumer of the barrel ships the faces. `fonts.css` declares two
families from `src/assets/fonts`: **Golos Text** (all six weights in
`src/assets/fonts/Golos` — Regular, Medium, SemiBold, Bold, ExtraBold, Black) and
**Inter** (Regular, Medium, Bold, `src/assets/fonts/Inter`). No licence or
attribution file accompanies them — verified: `src/assets` contains no
`LICENSE`/`OFL`/`README` of any kind — so the redistribution terms under which
the toolkit ships these binaries are unrecorded. That gap is DEV-43.
